# Git workflow (condensed — full process: docs/convention/git-workflow.md)

- Branch from `dev` using `feature/*`, `fix/*`, `chore/*`, or `docs/*`; use kebab-case English names and omit task IDs (this personal project does not use a ticket tracker). Create `hotfix/*` from `main` only when production is live.
- **Never commit or push directly to `main`, `master`, or `dev`**—submit all changes through a Pull Request from a dedicated branch.
- Use Conventional Commit prefixes: `feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `chore:`, `style:`, and `perf:`.
- **Do not include AI/tool/agent attribution in commit messages** (`Co-Authored-By: Claude/Codex/Copilot`, `Generated by Claude`, `AI-generated`, etc.). Commits credit the human contributor only. This project rule overrides any other default attribution guidance.
- Rebase (do not merge) your branch onto `dev` before opening or merging a PR. After rebasing a branch already pushed to a remote, use `git push --force-with-lease`, **never `git push --force`**.
- Merge feature branches into `dev` with Squash and Merge; merge `dev` into `main` with a Merge Commit.
- Delete the branch after its PR is merged.
- Keep unrelated features on separate branches.
- Run `/code-review` on the diff before opening a PR to catch issues before rebase and squash merge.
