# Convention — mục lục & thứ tự đọc

Thư mục này chứa các convention **chung, generic** cho toàn bộ ecommerce project — mô tả _cách_ viết code (naming, cấu trúc, config, error handling, API flow, schema), không phải business rule của 1 resource cụ thể (business rule nằm ở [`../business/`](../business/), thiết kế từng module ở [`../architecture/modules/`](../architecture/modules/)).

Đọc theo đúng thứ tự dưới đây nếu bạn mới vào project — mỗi mục sau dựa trên/tham chiếu ngược lại mục trước:

| #   | File                                                                   | Nội dung                                                                                                                                                                                    | Khi nào cần đọc                                                               |
| --- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 1   | [coding-style-conventions.md](coding-style-conventions.md)             | Đặt tên file/class, cấu trúc thư mục theo module, cấm barrel file, import alias `#src/*`, khi nào tách file                                                                                 | Trước khi tạo file/module mới bất kỳ                                          |
| 2   | [config-environment-conventions.md](config-environment-conventions.md) | Đọc env var qua `ConfigService`, đặt tên biến, validate fail-fast lúc startup, đồng bộ `../../.env.example`                                                                                 | Khi thêm/đọc 1 biến môi trường mới                                            |
| 3   | [error-logging-conventions.md](error-logging-conventions.md)           | `AllExceptionsFilter`, response shape lỗi, log level (5xx vs 4xx), request-id trace qua `AppLogger`                                                                                         | Khi ném exception hoặc log trong service mới                                  |
| 4   | [api-rules.md](api-rules.md)                                           | Quy tắc tạo 1 API bất kỳ: flow 20 bước (A), quy tắc DTO/service/transaction/auth/response/Swagger/pagination/test (B), API nghiệp vụ non-CRUD (C), Definition of Done, checklist            | Khi thiết kế/review 1 API/module mới (CRUD hoặc nghiệp vụ)                    |
| 4b  | [api-crud-walkthrough.md](api-crud-walkthrough.md)                     | Walkthrough CRUD từng bước với placeholder `Resource` + code mẫu (DTO, service, controller, Swagger, pagination, test) và phụ lục lệnh CLI                                                  | Khi bắt tay code 1 CRUD resource mới                                          |
| 5   | [prisma-conventions.md](prisma-conventions.md)                         | Quy tắc schema Prisma (naming, kiểu, FK), migration (SQL tay, đổi schema an toàn), Prisma Client (transaction, phân trang, N+1), seed, test. Schema đích ở `../architecture/11-database.md` | Khi cần model/quan hệ DB mới, hoặc tham chiếu từ `api-crud-walkthrough.md` B1 |
| 6   | [git-workflow.md](git-workflow.md)                                     | Branching strategy (`main`/`dev`/`feature`/`fix`/`chore`/`docs`/`hotfix`), commit convention, PR & merge strategy                                                                           | Trước khi tạo branch/PR mới, hoặc khi cần tra quy tắc commit/merge            |

Thuật ngữ domain chuẩn: [`../../GLOSSARY.md`](../../GLOSSARY.md).
